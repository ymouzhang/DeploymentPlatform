# PRD

> 管理员侧后续优化方向见[管理员产品优化路线图](./admin-product-optimization.md)。所有新增或改变产品行为的功能必须先更新本文档，再进入编码。

## 1. 产品概述

本产品为 Web 管理后台，用于配置目标服务器、管理服务安装包，并通过 SSH 完成服务的安装、启动、停止和状态检查。

- 支持用户选择已有服务类型，或在上传安装包时创建自定义服务类型。
- 服务类型使用稳定的小写标识，例如 `image-forward`、`video-forward`。
- 管理后台使用本地用户名和密码登录，并按账号隔离业务数据。

### 1.1 账号与权限

- 系统包含管理员和普通账号两种角色。
- 首次启动时通过环境变量创建唯一的初始管理员；环境变量中的密码属于临时密码，初始管理员首次登录后必须先自行修改密码，才能访问业务功能。初始管理员创建完成后，后续启动不得因环境变量变化而自动重置其用户名或密码。
- 管理员可以查看和操作所有账号的安装包、运行环境、部署服务、实例配置、操作记录和实时日志，并可按所属账号筛选列表。
- 普通账号只能查看和操作自己的安装包、运行环境、部署服务、实例配置、操作记录和实时日志。后端必须逐请求校验数据归属，不能仅依赖前端隐藏入口。
- 管理员新增资源时，资源默认归当前登录的管理员，不默认代其他账号创建；管理员操作其他账号已有资源时必须保留该资源原归属。
- 不同账号允许分别创建相同的服务类型，例如两个账号都可以拥有自己的 `image-forward` 安装包，且包文件和元数据互不影响。
- 管理员支持新增账号、重置账号密码、启用或禁用账号、删除账号。存在安装包、环境或历史操作等业务数据的账号不允许删除，必须先清理业务数据。
- 管理员新增的普通账号或管理员账号均使用管理员分配的临时密码，创建时固定标记为“待首次改密”，不提供关闭选项；新账号首次登录后必须由账号本人修改密码。
- 初始管理员和当前登录账号不允许被删除或禁用，避免系统失去可用管理员或当前会话状态自相矛盾。
- 普通账号和管理员均可修改自己的密码。修改密码、管理员重置密码或禁用账号后，该账号已有登录会话全部失效。
- 禁用账号不能登录；已经建立的会话也不得继续访问 API。用户名和密码校验正确但账号已被禁用时，登录页面明确提示“账号已被禁用”；密码错误时不得泄露账号是否存在或是否禁用。
- 登录、退出、当前账号查询和修改本人密码不属于业务数据操作，但仍需遵守同源请求和安全 Cookie 规则。
- 版本升级时，已有安装包、环境、服务配置和操作记录全部自动归属初始管理员，不要求人工迁移。

### 1.2 管理审计

- 管理员侧边栏增加“审计日志”页面；普通账号不可查看审计日志，也不可调用审计查询和导出接口。
- 审计日志用于回答“谁在何时、从哪里、对哪个账号的什么资源、执行了什么操作、结果如何”，与展示远程脚本输出的服务操作日志相互独立。
- 审计范围覆盖管理员和普通账号的关键行为，而不只记录管理员行为；管理员可据此追溯普通账号对自身资源的变更，以及管理员跨账号操作。
- 以下事件必须记录成功与失败结果：
  - 认证安全：登录成功、登录失败、禁用账号尝试登录、退出、修改本人密码。
  - 账号管理：新增账号、管理员重置密码、启用、禁用、删除账号。
  - 安装包管理：上传新版本、修改备注、切换当前版本、删除历史版本和删除安装包。
  - 环境管理：新增、修改、删除、SSH 校验、批量导入、环境导出，以及资源标签新增、修改和删除。
  - 服务管理：保存或回滚实例配置、安装、启动、停止、重置和手动健康检查。
  - 审计管理：查看审计详情和导出审计日志。普通列表翻页和筛选不逐次记录，避免审计读取产生无限递归和噪声。
- 服务安装、启动、停止和重置是异步行为：审计日志分别记录“已发起”和最终“成功 / 失败 / 超时 / 中断”，并关联同一个操作 ID。
- 审计内容不得保存登录密码、SSH 密码或密文、会话 Token、Cookie、安装包内容、完整实例配置、完整请求体及远程 stdout/stderr。配置和密码类操作只记录“已变更”及允许公开的资源标识。
- 删除账号、环境或安装包后，相应审计记录仍须保留；页面使用事件发生时保存的用户名、资源名称、IP 和服务类型快照展示，不依赖已删除业务表。

#### 审计页面

- 页面顶部展示最近 24 小时事件数、失败事件数、登录失败数和高风险操作数；统计基于当前筛选条件，并明确显示统计时间范围。
- 列表按时间倒序展示：时间、操作账号、角色、事件类型、操作对象、资源所属账号、来源 IP、结果和请求 ID。
- 支持按时间范围、操作账号、资源所属账号、事件分类、具体操作、结果和来源 IP 筛选；支持按用户名、资源名称、服务器 IP、服务类型、操作 ID 或请求 ID 检索。
- 默认查看最近 24 小时，使用服务端游标分页；管理员可展开详情抽屉查看目标快照、脱敏后的字段变更摘要、错误码、请求 ID、操作 ID 和 User-Agent。
- 高风险事件使用醒目标识，包括：连续登录失败、账号禁用或删除、管理员重置他人密码、删除安装包或环境、跨账号资源变更、环境/审计数据导出。
- 支持将当前筛选条件下的审计记录导出为 UTF-8 CSV；导出本身产生一条高风险审计事件。导出设置最大时间跨度和最大记录数，超过限制时提示缩小范围。
- 审计记录只读，页面不提供编辑和单条删除入口。
- 审计覆盖全部账号的关键行为，但只有管理员可以查看和导出。
- 审计日志默认保留 180 天，部署时允许通过环境变量调整；后台按日小批量清理过期记录。
- 同一规范化用户名或来源 IP 在 10 分钟内累计登录失败 5 次后，相关事件标记为高风险。
- 审计 CSV 单次导出时间范围不得超过 31 天，记录数不得超过 100,000 条。

### 1.3 管理员总览

- 管理员登录后默认进入 `/dashboard`；普通账号继续进入安装包管理，且不能访问总览接口或页面。
- 总览展示账号总数、启用/禁用账号数、安装包数、环境数、已安装服务数、运行中服务数、执行中操作数、最近 24 小时失败操作数、登录失败数、高风险审计数、未读通知数和当前管理员的未读通讯消息数。
- 总览展示 SSH 未校验、超过 30 天未校验的环境数量，以及非运行状态的已安装服务数量。
- “待处理事项”分为“待处理消息”和“风险通知”：消息区最多展示当前管理员最近 5 个含未读收件消息的通讯事项，展示目标账号、未读数、最新消息摘要和更新时间，点击进入对应事项；风险区保留最近未处理通知及原有跳转。
- 待处理消息数按当前管理员账号独立计算，不得将其他管理员的已读状态视为当前管理员已处理。
- 总览指标以服务端聚合为准；健康状态使用当前内存快照，不因打开总览而对远端主机发起额外检查。

#### 待处理消息验收结果（2026-08-14）

- 管理总览 API 已聚合当前管理员的未读通讯总数和最近 5 个未读事项，不与其他管理员已读状态混用。
- 待处理事项已分为“待处理消息”和“风险通知”，展示独立数量、空状态和摘要；消息可直达对应事项，“查看全部”自动带入未读筛选。
- 通讯 SSE 事件已同步失效管理总览缓存；后端角色与聚合测试、OpenAPI 契约测试、前端组件与缓存测试、类型检查及生产构建均通过。

### 1.4 数据范围与资源归属

- 管理员页面顶部筛选器命名为“数据范围”，并持续展示“全部账号”或具体账号，不能让用户误解为当前操作身份。
- 管理员新建安装包或环境时必须在表单内展示“所属账号”，并始终默认当前登录管理员；“数据范围”筛选不得改变新增资源归属。
- 普通账号不能指定其他所属账号，后端始终强制使用当前账号；管理员指定的所属账号必须存在且启用。
- 安装包、环境和服务继续以独立列展示所属账号。管理员修改、删除或执行其他账号资源时，确认信息同时展示资源名称和所属账号。
- 跨账号新建、配置修改、删除和服务生命周期操作均记录高风险审计。

### 1.5 全局操作中心

- 新增仅管理员可见的 `/operations` 页面，集中展示全部账号的安装、启动、停止和重置操作。
- 支持按操作账号、资源所属账号、操作类型、状态、时间和关键字筛选；关键字匹配环境名称、服务器 IP、服务类型、错误码和操作 ID。
- 列表展示操作账号、所属账号、环境、服务器、服务类型、动作、阶段、状态、持续时间、失败摘要、创建时间和关联请求 ID，并使用稳定游标分页。
- 操作详情可重新打开历史 JSONL 日志；执行中的操作继续通过 SSE 追踪，历史终态操作直接读取已保存日志。
- 操作记录保存发起时的账号、所属账号、环境、IP 和服务类型快照。环境删除或资源转移不得删除、改写历史操作及日志。
- 操作中心与审计日志通过操作 ID 相互跳转；操作中心用于故障处置，审计日志用于行为追责。失败操作按错误类型提供安装包、环境、配置或日志的精确处置入口。
- 操作记录和 JSONL 日志默认保留 180 天，可由部署参数调整；后台每日只清理已进入终态且超过保留期的操作，运行中操作不得清理。环境删除不提前删除其历史操作。

### 1.6 账号生命周期与资源交接

- 账号管理提供详情抽屉，展示账号基本信息、安装包/环境/已安装服务数量、最近 30 天操作数、有效会话数、最近登录、最近活动、最近来源 IP、登录失败数和高风险事件数。
- 管理员可强制撤销目标账号全部会话；不能对当前登录账号执行该操作。禁用、管理员重置密码和资源交接成功后同样撤销目标账号会话。
- 账号资源交接将该账号的全部安装包、环境及其服务配置原子转移给另一个启用账号；目标不能是源账号。
- 交接前只要存在运行中操作、目标账号同名安装包，或目标账号存在相同 `IP + service_type` 环境，整批交接即拒绝并返回明确冲突原因，不允许部分成功或静默覆盖。
- 交接只改变当前业务资源归属；既有操作和审计保存原所属账号快照。交接成功产生高风险审计并撤销源账号全部会话。
- 推荐离职流程为“禁用并下线 → 查看资源盘点 → 交接或清理 → 确认无资源 → 删除账号”。
- 账号确认无安装包和环境后删除时，其未使用的标签字典随账号一并清理；操作记录中的标签快照不受影响。

### 1.7 管理员风险通知

- 新增仅管理员可见的通知中心，并在导航展示未读数量。
- 以下事件生成持久化通知：连续登录失败达到高风险阈值；账号禁用、删除或管理员重置密码；跨账号资源变更；安装、启动、停止或重置失败/超时/中断；环境或安装包删除；数据导出。
- SSH 主机指纹变化、已安装服务连续三次健康检查不可达、数据目录可用空间低于 1 GiB 或 10%、审计清理失败同样生成高风险通知；连续登录失败按“规范化用户名或来源 IP + 时间窗口”去重，资源和系统故障按稳定目标键去重，同一事项未处理前不重复创建通知。应用重启不得破坏去重状态。
- 通知保存事件发生时的标题、摘要、风险级别、目标快照、操作 ID 和跳转地址，不依赖业务资源继续存在。
- 通知支持未读、已读和已确认处理三种进度；打开详情标记已读，管理员可显式确认处理。任一管理员的处理状态对所有管理员可见并记录处理人和时间。
- 通知按时间倒序分页，支持未读和风险级别筛选；普通账号不能查看数量、列表或修改状态。
- 已处理通知默认保留 180 天，可由部署参数调整；未处理通知不因超过期限自动删除。后台每日小批量清理过期的已处理通知。

### 1.8 账号安全基线

- 新安装实例初始化管理员时，以及管理员新增任意角色账号时，服务端必须设置 `must_change_password=true`。该规则只作用于初始化或创建动作，不在版本升级时追溯修改既有正常账号，避免无预警中断已有管理员访问。
- 账号可查看本人全部有效会话，信息包括登录时间、最近活动时间、来源 IP、浏览器/客户端摘要和过期时间，并能识别当前会话。账号可撤销任意指定会话；撤销当前会话后立即退出登录。
- 管理员可在账号详情查看目标账号的有效会话并撤销指定会话，也可继续撤销目标账号全部会话。管理员通过账号管理入口操作自己时，不允许误撤销当前管理会话；本人当前会话应从个人会话入口撤销。
- 管理员重置密码时，“下次登录必须修改密码”默认开启并允许显式关闭。开启后目标账号的既有会话全部撤销；目标账号使用临时密码登录后，只能查询当前账号、修改本人密码或退出，其他 API 返回 `403 PASSWORD_CHANGE_REQUIRED`。
- 强制改密仍要求输入当前临时密码。修改成功后清除强制改密标记并撤销该账号全部会话，页面跳转登录页，使用新密码重新登录。
- 登录失败同时按规范化用户名和可信来源 IP 统计。任一维度在滚动 10 分钟窗口达到 5 次失败后限制继续尝试，退避时间从 30 秒指数增长，最长 15 分钟；受限请求返回 `429 LOGIN_THROTTLED`，不得泄露账号是否存在。成功登录后清除该用户名和来源 IP 的失败状态。
- 启用、非初始管理员账号连续超过 `DP_STALE_ACCOUNT_DAYS` 未成功登录时生成普通风险级别的站内通知，默认阈值为 90 天；从未登录账号从创建时间计算。相同账号未处理前只保留一条提醒，成功登录后自动标记既有提醒已处理。
- 会话创建、指定会话撤销、全部会话撤销、管理员重置密码、强制改密成功和登录限流均进入审计；审计及接口响应不得包含会话 Token 或 Token 摘要。

### 1.9 管理员与用户通讯

- 通讯以“协作事项”为容器。只有管理员可以向一个启用的普通账号主动创建事项；普通账号不能创建事项、选择收件人或与其他普通账号通讯。
- 事项包含标题、消息时间线、唯一目标账号、关联资源、开启/关闭状态及不可变状态历史。事项只提供沟通上下文，不自动执行安装、启动、停止、重置，也不包含截止时间或任务进度。
- 管理员创建事项时可以关联目标账号名下零个或多个安装包、环境或服务，最多 50 个。任一资源无效或不属于目标账号时整次创建失败；关联只保存上下文，不改变资源归属。
- 所有管理员都可以查看全部事项和用户回执，并可在开启事项内继续发送消息。管理员消息只有目标用户是收件人；用户回执发送时，当时所有启用管理员分别成为收件人并独立维护未读状态。
- 标题长度为 1–100 个字符，普通消息和回执正文为 1–5000 个字符。消息按纯文本显示，创建后不可编辑、撤回或删除。
- 用户打开事项详情时，系统将本人收到的管理员消息和状态消息原子标记为已读；管理员可以逐条查看用户是否已读及首次已读时间。列表预览不能隐式标记已读。
- 普通账号只能在发给本人且状态为 `open` 的事项内发送回执。发送回执同时标记此前本人收件消息已读；回执对所有管理员可见。
- 管理员关闭事项后，系统追加明确的“事项已关闭，无法继续回复”状态消息并增加用户未读数；关闭后管理员普通消息和用户回执均不可继续追加。
- 管理员可以重新打开已关闭事项。系统必须记录重新打开次数、操作者和时间，追加“事项已重新打开，可以继续回复”状态消息并增加用户未读数；页面持续展示重新打开标识，不能把重新打开伪装成首次创建。
- 消息中心是管理员和普通账号共享的一级侧边栏导航，不得只能通过顶栏图标进入。侧边栏展示当前账号未读数，折叠时仍以提示点表达有未读消息。
- 顶栏保留通讯消息快捷入口；有未读时同时使用高对比图标容器、轻量动效和数字徽标，超过 99 显示 `99+`，无未读时恢复中性样式。通讯消息与现有管理员风险通知分开存储和展示。
- 登录账号建立一个全局实时事件连接。创建事项、管理员消息、用户回执、已读、关闭和重新打开在事务成功后应立即通知受影响账号，使未读徽标、事项列表、打开的时间线和用户已读状态无需刷新页面即可更新。
- 实时连接只发送事件类型、事项 ID 和发生时间等刷新提示，不发送消息正文、账号凭据或资源详情；客户端收到事件后仍通过现有授权接口读取数据库中的权威数据。
- 实时连接断开不得影响消息持久化或发送。连接建立和自动重连后必须立即同步通讯摘要、列表及当前打开详情；保留 30 秒轮询作为断线、代理不兼容或浏览器节流时的最终兜底。
- 一个浏览器标签页只建立一个账号级实时连接，不按事项分别建立连接。后台标签页也应依赖实时事件更新；恢复到前台时再次同步，不能要求用户手动刷新。
- 事项和消息保存账号与资源快照。资源删除、改名、转移或账号删除不得破坏历史时间线；失效资源展示原名称并提示不存在或无权访问，点击时仍执行当前权限校验。
- 所有管理员可查看历史事项。用户回执仅对发送时已经启用的管理员产生未读记录，后续新增或重新启用的管理员可以查看历史但不会继承加入前的未读数量。
- 创建、管理员发送、用户回执、已读、关闭和重新打开进入审计；审计只保存事项、参与账号、消息类型、正文长度和资源数量等摘要，不保存完整正文。
- 首版不支持多用户收件人、群聊、附件、富文本、消息编辑/撤回、外部推送、自动催办和通讯记录物理删除。

## 2. 服务器配置

### 2.1 运行环境

一个运行环境对应一台服务器，包含以下信息：

- 环境名称
- 服务器 IP
- SSH 用户名，默认为 `aaron`
- SSH 端口，默认为 `22`
- SSH 密码，仅支持密码登录，密码需加密存储
- 服务安装目录；目录不存在时支持自动创建
- 服务类型
- 备注：可选，最多 200 字；新建和编辑环境时均可填写或清空，列表中以单列展示，内容超长时截断、鼠标悬浮显示全文。
- 服务器架构：由系统通过 SSH 执行 `uname -m` 自动采集并展示（去除首尾空白），不需要用户填写；未采集时显示 `-`。架构在 SSH 校验成功或服务安装成功后自动更新，编辑或导入环境不会覆盖已采集的架构。

同一账号可以在一台服务器上配置多个不同类型的服务，但不允许配置多个相同类型的服务；不同账号之间互不占用该唯一组合。

环境信息需要持久化存储，管理后台或服务重启后数据不得丢失。SSH 密码在持久化存储中必须保持加密状态，仅在服务端执行 SSH 连接等需要使用密码的操作时解密。

### 2.2 SSH 信息校验

提供一键校验 SSH 信息功能，校验内容包括：

1. SSH 是否可以成功连接。
2. 服务安装目录是否存在；不存在时能否创建。
3. 是否具备向服务安装目录上传文件的权限。

### 2.3 环境信息导入与导出

- 支持将环境信息导出为 JSON 文件。
- 支持通过 JSON 文件批量导入环境信息。
- 导入前需校验文件格式和环境字段的有效性；校验失败时向用户展示具体错误。
- 在当前数据归属账号内，使用“服务器 IP + 服务类型”作为环境信息的唯一冲突判断条件。
- 导入的数据与已有环境发生冲突时，直接使用导入的数据覆盖原环境信息，不保留备份。
- 导入成功的环境信息需要持久化存储。
- 导出文件包含 SSH 密码，但密码必须以加密数据的形式导出，不得包含明文密码。
- 导出的 JSON 文件支持导入到另一套管理后台。
- 另一套管理后台导入后，必须能够解密其中的 SSH 密码，并正常执行 SSH 校验、安装、启动和停止等操作。
- 每套管理后台通过环境变量配置密码加密主密钥。
- 跨管理后台迁移时，源管理后台与目标管理后台配置相同的主密钥，目标管理后台即可解密导入的 SSH 密码。
- 主密钥不得写入数据库、导出的 JSON 文件、接口响应、操作日志或脚本执行结果窗口。
- SSH 密码明文不得通过管理接口返回，也不得写入操作日志或脚本执行结果窗口。
- 普通账号只能导入和导出自己的环境。管理员默认导入到当前管理员名下，并可按账号筛选后导出对应账号的环境；导入不得隐式创建或改变数据所属账号。

### 2.4 环境检索与删除

- 环境列表以独立的“所属账号”列展示该环境由哪个账号创建；管理员和普通账号均可见。
- 环境列表支持按服务器 IP 或服务类型检索，分页展示，默认每页 10 条。
- 支持删除环境；已安装服务或有操作执行中的环境不允许删除，需先在服务管理页完成重置。
- 删除环境时同步删除该环境的实例配置及其修订历史；历史操作记录和操作日志按运维历史保留期继续保存，展示创建时的资源快照。远端服务器上的服务文件不做处理，由用户自行清理。

### 2.5 资源标签与分组

- 标签以“分组 + 值”组成，例如“环境阶段 / 生产”“区域 / 华东”“项目 / 智慧交通”。分组和值去除首尾空白后均为 1–32 个字符，同一账号内组合唯一，大小写不敏感。
- 环境可以关联多个标签；服务实例继承所属环境标签。生产、测试、开发等属性属于环境，不直接绑定安装包。
- 用户可新增、重命名和删除自己账号下的标签。管理员可维护任意账号标签，但新建标签必须明确所属账号；普通账号不能读取或引用其他账号标签。
- 环境新建和编辑表单允许选择同一所属账号的标签。标签调整与环境其他字段在同一次保存中生效；跨账号标签 ID、无效标签 ID 或重复标签 ID 必须拒绝，不能部分保存。
- 删除标签只解除其与环境的关联，不删除环境、服务、配置或操作历史。删除前界面展示关联环境数量。
- 环境管理和服务管理展示标签，并支持选择多个标签筛选；多个标签采用“同时满足”语义，关键字和标签条件同时生效。
- 管理总览的标签筛选只影响环境、已安装服务、健康状态、SSH 校验和操作类指标；账号、安装包、登录失败、高风险审计、通知及待处理事项维持全局口径，页面必须说明该差异。
- 操作发起时保存环境标签快照。操作中心按快照筛选和展示，因此后续标签改名、解绑、删除或环境删除不会改变历史操作的筛选结果。
- 资源交接时，在目标账号下按“分组 + 值”复用或创建等价标签并重新关联环境；源账号标签字典不自动删除。
- 环境导出文件使用 schema v2 并包含每个环境的标签组合；导入兼容 schema v1。v1 记录按无标签导入，v2 标签在目标账号下复用或创建，整个导入仍保持原子性。
- 标签只用于组织、检索和后续批量选择，不构成授权条件；后端始终先校验账号归属，再处理标签筛选或关联。

## 3. 服务管理

### 3.1 服务列表

按照服务类型展示所有已配置的运行环境。

每个服务展示以下信息：

- 服务名称（服务类型）
- 所属账号：以独立列展示创建该服务环境的账号
- 环境名称
- 服务器 IP
- 服务端口：优先展示该服务实例独立配置中的实际端口；尚未形成独立配置时展示安装包模板中的默认端口。
- 服务状态

部署状态除“未安装 / 已安装”外，还需区分“安装失败”：最近一次安装操作失败、超时或被中断（例如容器 unhealthy 导致 `start.sh` 退出码非零），且此后未成功重置时，部署状态显示“安装失败”并提示失败原因，不得显示“未安装”——此时安装包已上传解压、远端可能仍有容器在运行。重置成功后恢复显示“未安装”。

服务列表支持按服务器 IP 或服务类型检索，分页展示，默认每页 10 条。

每个服务提供以下操作：

- 配置
- 安装
- 启动
- 停止
- 重置

无论服务是否安装成功，“重置”操作始终可用：安装失败后远端服务可能仍在运行（例如 docker compose 反复重启），用户可通过重置强制停止远端服务并清理安装标记，避免服务器上残留异常服务。

### 3.2 安装包管理

- 安装包由用户上传。
- 安装包列表以独立的“所属账号”列展示上传并拥有该安装包的账号；管理员和普通账号均可见。
- 安装包仅支持 `.tar.gz` 格式。
- 上传时必须选择已有服务类型，或输入一个新的自定义服务类型。
- 在同一所属账号内，服务类型与安装包一一关联；服务类型以安装包记录为唯一数据来源，不重复维护类型表。
- 每个账号的每个服务类型维护一个当前安装包版本，并保留历史版本。
- 上传新文件创建不可变版本并将其设为当前版本；仅修改备注时更新当前版本备注，不创建新版本。
- 安装包版本展示版本 ID、SHA-256、大小、上传人、上传时间、备注、配置路径、格式、默认端口和校验结果。
- 历史版本默认保留 10 个，可由部署参数调整。超过数量时只清理既非当前版本、也没有被环境安装引用的最旧版本。
- 管理员和普通账号都可查看自己权限范围内的版本历史；管理员跨账号查看或操作时必须显式传递所属账号。
- 可将配置格式和路径与当前版本兼容的历史版本重新设为当前版本。切换当前版本只影响后续安装，不自动重装已有环境。
- 当前版本不得删除；已被任一环境通过 SHA-256 引用的版本不得删除。删除前展示引用环境数量。
- 上传安装包时可添加可选备注（最多 200 字）；安装包列表在“当前安装包”右侧以单列展示备注，内容超长时截断、鼠标悬浮显示全文。
- 每行提供“更新”入口：可选地替换安装包文件、修改备注或两者同时更新；未选择文件时保留当前安装包，未填写备注时保留原有备注。
- 安装包列表展示从配置模板解析出的“默认配置端口”，该值不代表所有服务实例的实际端口。
- 安装包列表的文件名保持单行展示，超长时省略并可悬浮查看全文；SHA-256 摘要使用等宽样式与文件名形成主次层级，不得因逐词换行撑高整行。
- 安装包列表在宽度不足时使用表格横向滚动，保持文件信息、备注和版本/更新/删除操作的可读性，不通过无限压缩列宽适配。
- 安装包中的配置文件是服务实例配置的初始模板，不允许在安装包管理页面直接编辑。
- 为保护已有实例配置，替换安装包时不得改变配置文件的 JSON/YAML 格式或解压后的相对路径。
- 支持按服务类型检索安装包，列表分页展示，默认每页 10 条。
- 支持删除安装包；该服务类型下存在已安装服务的环境时不允许删除，需先重置相关环境。删除安装包只移除管理后台中的包文件和元数据，不影响已部署到服务器上的服务。

### 3.3 服务配置

1. 支持以下四种配置文件路径（YAML 场景同时兼容 Java/Spring 风格的 `application.yml`）：
   - `config/config.json`
   - `config/config.yaml`
   - `config/application.yml`
   - `config/application.yaml`
2. 安装包内容可以直接位于压缩包根目录，也可以统一放在一个单层公共根目录中，例如 `dist/config/config.yaml`、`dist/start.sh` 和 `dist/stop.sh`。
3. 使用单层公共根目录时，安装包中的所有文件必须位于该目录下；安装解压时自动剥离公共根目录。
4. 安装包必须包含且只能包含上述一种配置文件；如果多种文件同时存在，则安装包校验失败。
5. 如果 `start.sh` 显式指定了配置文件路径，该路径必须与安装包实际提供的 JSON/YAML 配置一致，否则安装包校验失败。
6. 配置按“服务器 IP + 服务类型”绑定并持久化保存；同一服务安装到不同服务器时，各服务实例的配置相互独立。
7. 服务实例尚未保存独立配置时，以安装包内的配置作为初始模板。
8. 在服务管理页面点击对应实例的“配置”后，通过文本编辑器展示该实例配置，编辑器根据文件格式切换 JSON 或 YAML 语法高亮。
9. 保存前必须根据模板的原配置文件格式进行 JSON 或 YAML 格式校验；格式错误时不允许保存，并向用户展示错误信息。
10. 保存实例配置不得修改或重新压缩公共安装包，也不得影响同服务类型的其他服务器。
11. 安装服务时，解压公共安装包后、执行脚本前，将该实例的独立配置覆盖写入对应的配置文件（`config/config.json`、`config/config.yaml`、`config/application.yml` 或 `config/application.yaml`）。
12. 打开配置编辑器时，以当前有效配置为基线；保存前必须展示当前内容与待保存内容的并排差异，内容完全相同时不创建新修订。
13. 每次手工保存配置都创建不可变修订，记录操作者、创建时间和来源；首次从安装包模板保存时，保存后的内容成为第一个实例修订。
14. 配置历史按时间倒序展示，支持查看任一修订全文。回滚不会删除后续历史，而是以目标修订内容创建一个来源为“回滚”的新修订，并记录来源修订 ID。
15. 回滚与普通保存使用相同的格式校验和远端同步规则；远端写入失败时不得创建本地修订。已安装环境回滚成功后同步更新健康检查端口。
16. 普通账号只能查看和回滚自己的环境配置；管理员可以操作全部账号环境，并记录资源所属账号、操作者和高风险跨账号审计。
17. 删除环境时级联删除实例配置修订；审计事件仍保存配置变更的脱敏摘要，不保存配置正文。

本阶段不采集远端实际配置，不判断绕过 DP 的人工修改，也不提供跨环境批量覆盖；这些能力后续单独设计。
12. 已安装服务的配置保存成功后，立即通过 SSH 覆盖远端服务目录中的对应配置文件，并同步更新健康检查端口；是否需要重启服务由具体配置决定。

### 3.4 服务安装

安装流程如下：

1. 通过 SSH 连接目标服务器。
2. 创建服务安装目录（如果目录不存在）。
3. 将当前服务类型明确指向的当前安装包版本上传至目标服务器，并固定记录该版本 SHA-256。
   服务类型由环境配置确定，系统自动匹配，不由用户手动选择安装包版本。
4. 在服务安装目录中解压安装包。
5. 将当前服务器服务实例的独立配置写入解压目录。
6. 在解压后的目录中优先执行 `install.sh`。
7. 如果安装包中不存在 `install.sh`，则执行 `start.sh`。
7. 安装成功后，该服务被标记为已安装，不允许再次执行安装操作。
8. 点击“安装”后弹出执行结果窗口，实时展示上传、解压及脚本执行过程。
9. 脚本输出、执行错误及超时错误均直接展示在执行结果窗口中。
10. 脚本执行超时时间为 3 分钟。

### 3.5 服务启动

- 在服务安装目录中执行 `start.sh`。
- 点击“启动”后弹出执行结果窗口，实时展示脚本执行结果。
- 脚本输出、执行错误及超时错误均直接展示在执行结果窗口中。
- 脚本执行超时时间为 3 分钟。

### 3.6 服务停止

- 在服务安装目录中执行 `stop.sh`。
- 点击“停止”后弹出执行结果窗口，实时展示脚本执行结果。
- 脚本输出、执行错误及超时错误均直接展示在执行结果窗口中。
- 脚本执行超时时间为 3 分钟。

### 3.7 服务状态

1. 从当前服务器服务实例的独立配置中读取端口，依次支持顶层 `port` 和嵌套字段 `server.port`。
2. 使用服务器 IP 和端口拼接健康检查地址：

   ```text
   http://<服务器IP>:<port>/health
   ```

3. 健康检查接口应返回 JSON 数据。
4. 当接口返回数据中的顶层 `status` 字段为字符串 `"health"` 或 `"healthy"` 时，服务状态为“运行中”；匹配区分大小写，其他值或类型均视为非运行状态。

#### 健康状态兼容验收（2026-08-14）

- 已验证 `{"status":"health"}` 和 `{"status":"healthy"}` 均归一为 `running`。
- 已验证 `unhealthy`、大写 `HEALTHY` 及非字符串值不会被误判为运行；OpenAPI 契约校验、健康检查单元测试和 `go vet ./...` 均通过。

### 3.8 服务重置

- 已安装服务提供“重置”操作，用于重新安装，或解除服务器 IP、服务类型和安装目录的编辑限制。
- 未安装的服务（包括安装失败的情况）同样提供“重置”操作：安装失败后远端服务可能仍在反复重启，重置用于强制停止远端残留服务并清理安装标记。
- 重置属于异步操作，必须通过执行结果窗口实时展示停止脚本、远端标记处理和本地状态更新过程。
- 如果该服务最近一次成功的生命周期操作不是“停止”，重置前必须自动执行一次 `stop.sh`；远端不存在 `stop.sh` 时（例如安装中途失败）跳过停止脚本，继续清理安装标记。
- `stop.sh` 执行失败或超过 3 分钟时，重置失败，不得修改远端安装标记或本地安装状态。
- 停止成功后，删除远端 `.dp-installed.json`，并写入 `.dp-installing.json`，允许在原目录重新安装和覆盖已有文件。
- 重置不删除远端安装目录、配置或业务文件。
- 远端标记处理成功后，将本地服务状态改为“未安装”，并清空安装时间、已安装包 SHA-256 和健康检查端口。
- 重置完成后允许修改服务器 IP、服务类型和安装目录；修改服务类型时，原实例配置失效，下次读取新类型安装包中的配置模板。
- 如果重置后修改了服务器 IP 或安装目录，旧位置会保留已经停止的文件，由用户自行处理。
