# DP 模型管理需求与设计

> 文档状态：第一阶段已按远端暂存方案实现  
> 更新时间：2026-08-31  
> 关联文档：[PRD](./prd.md) · [架构设计](./architecture.md)

## 1. 目标

在侧边栏“环境管理”下方增加“模型管理”。用户选择已有环境作为目标主机，DP 复用该环境保存的
SSH 地址、账号、密码和主机指纹，把模型放入用户指定的目标绝对目录。

模型来源分为：

- 离线上传：用户上传 `.tar.gz`，DP 传到目标主机并在目标位置解压；
- 在线下载：目标主机从 ModelScope 或 Hugging Face 下载，国内默认优先 ModelScope。

模型是独立资源，不从属于某个 vLLM 或 SGLang 服务。多个推理服务可以在配置中引用同一个模型目录，
DP 第一阶段不自动修改推理服务配置，也不判断模型当前是否正在被进程使用。

## 2. 已确认决策

1. 目标主机从已有环境中选择，复用环境的 SSH 凭据，不新增独立主机表。
2. 在线下载不依赖目标机预装 ModelScope/Hugging Face CLI。DP 离线包携带固定版本下载器，使用时自动
   上传或加载到目标机。
3. 离线模型可能超过 30 GiB，必须使用分片、断点续传，不能使用一次性 multipart 上传。
4. 支持删除模型；删除必须有二次确认和远端安全标记校验。
5. 第一阶段优先实现离线上传。在线下载的数据库与接口预留可以同步设计，但不进入第一阶段验收范围。

## 3. 分阶段范围

### 3.1 第一阶段：离线上传

必须完成：

- 模型列表、账号范围筛选、关键字筛选；
- 选择已有环境、模型名称、目标绝对目录和本地 `.tar.gz`；
- 浏览器分片上传、暂停后继续、刷新页面后恢复；
- 上传可在关闭弹窗或切换 DP 页面后继续，期间必须保持当前浏览器标签页打开；刷新、关闭标签页或退出浏览器会中断，重新选择同一文件后可断点续传；
- DP 将浏览器分片流式中转到目标机暂存包，不在 DP 磁盘保存完整模型；
- 上传完成后自动上传固定摘要的本地校验器，在目标机执行安全检查和 SHA-256 计算；目标机架构不匹配或工具不可执行时回退到并发 SFTP 流式校验；
- 远端临时目录解压、完成后原子切换；
- 上传、传输、解压进度和任务日志；
- 失败重试和 DP 重启后的中断状态；
- 删除 DP 管理的远端模型目录；
- 账号隔离、管理员跨账号操作、审计事件；
- 远端暂存文件清理和容量配置。

第一阶段不包含：

- ModelScope/Hugging Face 在线下载；
- 自动修改 vLLM/SGLang 配置；
- 自动检测模型格式、量化方式、上下文长度或显存需求；
- 判断模型是否正被推理进程使用；
- 跨主机复制、模型版本升级和增量同步；
- 从目标主机反向扫描并导入已有模型。

### 3.2 第二阶段：在线下载

- 来源支持 `modelscope`、`huggingface`，表单默认 `modelscope`；
- 支持仓库 ID、可选 revision、可选访问 Token；
- 下载器及其 Python 依赖锁定准确版本，随 DP 离线部署包交付；
- 下载器自动传到目标主机，复用时按镜像或制品摘要校验，不重复传输；
- Token 仅在任务执行期间加密保存，不写日志，任务结束后删除；
- 下载到同盘临时目录，完成校验后原子切换到最终目录；
- 保留任务日志、失败重试、超时和清理规则。

## 4. 用户界面

### 4.1 导航

```text
安装包管理
环境管理
模型管理
服务管理
```

管理员在模型管理页使用现有“数据范围”筛选器；普通账号只看到自己的模型和环境。

### 4.2 模型列表

列表展示：

- 模型名称；
- 所属账号；
- 来源：离线上传、ModelScope、Hugging Face；
- 目标环境、服务器 IP；
- 目标目录；
- 压缩包 SHA-256、模型展开大小和文件数；
- 状态、当前进度和失败摘要；
- 创建人、创建时间、完成时间。

行操作：查看任务日志、继续上传、重试部署、删除。第一阶段在线来源入口显示“后续支持”，不提供可提交
表单。

### 4.3 新建离线模型

用户填写：

- 所属账号：管理员可选，普通账号固定为本人；
- 目标环境：只能选择所属账号下启用且有 SSH 密码的环境；
- 模型名称：1–128 个字符；
- 目标目录：规范绝对路径，例如 `/data/models/Qwen3-32B`；
- 模型包：文件名必须以 `.tar.gz` 结尾。

创建后进入上传任务。关闭弹窗、刷新浏览器或重新登录不会丢失已确认的分片；用户可从模型列表继续。

## 5. 第一阶段数据流

```text
浏览器
  │ 1. 创建上传会话
  │ 2. 按 offset 上传分片，DP 流式中转
  ▼
目标主机 .dp-model-upload-<upload-id>.tar.gz
  │ 3. 查询远端大小并续传
  │ 4. 目标机本地校验器计算 SHA-256 并检查 tar.gz，持续回传进度
  │ 5. 检查展开所需磁盘空间
  │ 6. 解压到同盘临时目录
  │ 7. 写入 .dp-model.json
  │ 8. 原子 rename 到最终目录并删除暂存包
  ▼
目标模型目录
```

只有第 8 步成功后模型状态才是 `ready`。任何前置步骤失败都不得把最终目录标记为可用。

## 6. 分片上传协议

第一阶段采用顺序 offset 协议，不一次上传整个文件：

1. `POST /api/v1/model-uploads` 创建会话，提交模型名称、环境 ID、目标目录、文件名和总大小；
2. `HEAD /api/v1/model-uploads/{id}` 返回服务器已经持久化的 `Upload-Offset`；
3. `PATCH /api/v1/model-uploads/{id}` 上传一个二进制分片，请求携带 `Upload-Offset`；
4. offset 不匹配返回冲突，客户端读取服务端 offset 后继续；
5. `POST /api/v1/model-uploads/{id}/complete` 完成上传并启动校验、远端传输任务；
6. `DELETE /api/v1/model-uploads/{id}` 取消尚未完成的上传并删除目标机暂存文件。

默认分片 64 MiB。DP 每个请求建立 SSH/SFTP 通道，把分片直接追加到远端暂存包；写入成功后才更新
PostgreSQL offset。同一上传会话只允许一个分片写请求，避免乱序覆盖。查询或续传时以远端实际文件大小校准
数据库 offset，DP 重启后仍可恢复。

建议新增配置：

| 配置 | 默认值 | 说明 |
| --- | ---: | --- |
| `DP_MODEL_UPLOAD_MAX_BYTES` | 1 TiB | 单个压缩包最大大小 |
| `DP_MODEL_UPLOAD_CHUNK_BYTES` | 64 MiB | 前端建议分片大小 |
| `DP_MODEL_UPLOAD_RETENTION` | 72h | 未完成上传保留时间 |
| `DP_MODEL_TRANSFER_TIMEOUT` | 24h | SFTP 与远端解压任务上限 |
| `DP_MODEL_TASK_CONCURRENCY` | 2 | 全局模型远端任务并发数 |

上传大小使用 `int64`。HTTP 反向代理必须允许单个分片大小，而不需要允许整个模型大小。

## 7. 压缩包校验与解压

完整上传后，DP 检测目标机 CPU 架构，将自身受限的 `model-validator` 子命令按可执行文件 SHA-256
缓存到环境安装目录的 `.dp-tools/`，在目标机本地读取暂存文件并检查。正常路径不把模型包读取回 DP，
校验器上传后会复用；架构不一致、工具目录不可写或禁止执行时，自动回退到并发 SFTP 流式校验：

- gzip 和 tar 结构有效；
- 不允许绝对路径、`..`、反斜杠和空字符；
- 只允许普通文件和目录，不允许符号链接、硬链接、设备、FIFO 等特殊条目；
- 文件数量、单文件大小和总展开大小不超过配置上限；
- 至少包含一个普通文件；
- 计算压缩包 SHA-256、普通文件数量和总展开大小。

如果所有内容都位于同一个公共顶层目录，解压时自动剥离该目录；否则保持压缩包原目录结构。

目标目录规则：

- 必须是规范绝对路径；
- 不允许 `/`、`/bin`、`/boot`、`/dev`、`/etc`、`/lib`、`/proc`、`/root`、`/run`、`/sbin`、
  `/sys`、`/usr`、`/var` 及这些目录本身；
- 最终目录必须不存在，第一阶段不覆盖、不合并已有目录；
- 临时包和临时目录使用任务 ID 命名，并位于最终目录的父目录，保证最终 rename 在同一文件系统内；
- 重试只能清理带当前任务 ID 的临时文件，不能清理未知文件。

## 8. 远端标记和删除

部署完成前，在临时模型根目录写入 `.dp-model.json`：

```json
{
  "schema_version": 1,
  "model_id": "<uuid>",
  "owner_id": "<uuid>",
  "source": "upload",
  "archive_sha256": "<sha256>",
  "created_at": "<RFC3339>"
}
```

删除采用以下顺序：

1. 用户输入模型名称二次确认；
2. 后端重新检查资源归属和目标环境；
3. SSH 读取目标目录 `.dp-model.json`；
4. 标记中的 `model_id` 与数据库模型 ID 一致，`owner_id` 与数据库保存的不可变 `marker_owner_id` 一致才允许继续；
5. 先把目录原子改名为同级 `.dp-model-trash-<task-id>`；
6. 异步删除 trash 目录；
7. 删除完成后更新数据库状态，保留任务和审计历史。

标记缺失或不匹配时拒绝远端删除，不提供“强制删除任意目录”。DP 无法确认模型是否正在被推理进程使用，
界面必须明确提示先停止引用该目录的服务。

## 9. 数据模型

### 9.1 `models`

建议字段：

- `id`、`owner_id`、`marker_owner_id`、`environment_id`；
- `name`、`source`；
- `original_filename`、`sha256`；
- `target_dir`、`environment_ip`、`environment_name`；
- `size_bytes`、`expanded_size_bytes`、`file_count`；
- `status`、`error_message`；
- `created_by`、`created_by_username`、`created_at`、`updated_at`、`ready_at`、`deleted_at`。

`source` 使用 `offline`，并预留 `modelscope`、`huggingface`。`marker_owner_id` 保存首次创建时写入远端
标记的 owner，资源交接只改变当前 `owner_id`，删除时仍可验证原始标记。同一账号、目标 IP、规范目标目录只能有一条未删除
记录，防止同一主机通过不同环境重复管理同一路径。

### 9.2 `model_uploads`

保存上传会话、预期大小、已接收 offset、远端暂存路径、状态、最后活动时间和过期时间。远端路径不通过 API
返回。上传完成并创建远端任务后仍保留元数据，暂存包在部署成功、取消或过期清理时删除。

### 9.3 `model_tasks`

模型任务与现有服务 `operations` 分表，避免模型上传影响服务页面的最近生命周期状态或长时间锁住服务
启停。字段包含模型 ID、动作、状态、阶段、进度、字节数、错误、JSONL 日志路径、操作者和目标快照。

第一阶段动作使用 `deploy`、`delete`；第二阶段再扩展在线下载动作。状态复用
`queued`、`running`、`succeeded`、`failed`、`timed_out`、`interrupted`。

DP 启动时把 `queued/running` 模型任务标记为 `interrupted`。上传会话仍可续传；远端任务由用户点击重试，
不在服务重启后自动执行。

## 10. 并发和环境约束

- 同一上传会话只允许一个分片请求；
- 同一模型只允许一个活动任务；
- 同一目标 IP 和目标目录只允许一个部署或删除任务；
- 模型任务不阻塞同环境的服务启动、停止，但删除前由用户负责停止引用模型的服务；
- 设置全局模型任务并发上限，首版默认 2，避免耗尽 DP 网络和目标机磁盘；
- 环境存在未删除模型时，不允许修改服务器 IP、SSH 用户或 SSH 端口，也不允许删除环境；允许更新 SSH
  密码和主机指纹校验结果；
- 账号资源交接必须连同模型、上传会话和任务快照一起处理；存在活动模型任务时禁止交接。

## 11. 权限、凭据和审计

- 普通账号只能查看、上传、部署和删除自己的模型；
- 管理员可以切换账号范围，但新建模型必须显式确定所属账号，目标环境必须属于同一账号；
- 已禁用账号不能创建上传会话或新模型；
- SSH 密码沿用现有 AES-GCM 解密流程，只在连接期间存在于内存；
- 模型文件内容、SSH 密码、在线 Token 不进入日志和审计；
- 审计至少记录上传会话创建/取消、上传完成、部署请求/结果、重试、删除请求/结果；
- 审计只记录模型 ID、名称、来源、目标环境、目标路径、大小和摘要。

## 12. 第二阶段固定下载器

下载器使用固定版本的 Python、ModelScope 和 `huggingface_hub`，构建为独立 Docker 镜像并导出为离线
镜像归档。DP 离线部署包同时携带该归档；DP 进程能够读取归档并通过 SFTP 传给目标主机。

目标任务流程：

1. 检查目标主机 Docker；
2. 按镜像 ID 判断下载器是否已加载；
3. 缺失时上传归档并执行 `docker load`；
4. 将目标目录父目录挂载给下载器；
5. ModelScope 执行 `modelscope download --model ... --local_dir ...`；
6. Hugging Face 执行 `hf download ... --revision ... --local-dir ...`；
7. 完成后写远端标记并原子切换。

下载器版本升级必须重新制作 DP 离线包。Token 通过权限为 `0600` 的临时环境文件传入，命令结束后立即
删除；命令行、任务日志和审计中不得出现 Token。

## 13. 第一阶段验收

1. 40 GiB 以上 `.tar.gz` 可以分片上传，中断和刷新后从服务端 offset 继续。
2. 越权访问、跨账号环境、错误 offset、超限文件和不安全 tar 均被拒绝。
3. DP 重启后上传会话可恢复，执行中的远端任务显示中断并可重试。
4. SFTP 或解压失败不会产生最终模型目录，也不会把模型标记为可用。
5. 最终目录已存在时拒绝部署，不覆盖原文件。
6. 成功模型具有正确 SHA-256、展开大小、文件数和 `.dp-model.json`。
7. 只有标记匹配的 DP 模型目录可以删除；标记缺失或不匹配时拒绝。
8. 普通账号隔离、管理员跨账号操作和审计记录正确。
9. 模型任务不会改变服务安装状态、最近生命周期操作和健康检查。
10. OpenAPI、后端单测/竞态检查、前端类型检查/测试/构建全部通过。
