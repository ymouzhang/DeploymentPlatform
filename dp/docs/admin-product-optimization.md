# DP 管理员产品优化路线图

> 文档状态：维护中
> 评审视角：管理员端产品体验、治理能力与运维效率
> 建立时间：2026-08-13
> 最近更新：2026-08-27
> 当前进度：健康接口状态值兼容、管理总览待处理消息、通讯实时化和近期界面优化已完成；其余尚未实施的既有优化统一暂缓
> 关联文档：[PRD](./prd.md) · [架构设计](./architecture.md) · [OpenAPI](../api/openapi.yaml)

## 1. 文档目的

DP 已具备账号隔离、管理员跨账号管理、远程服务生命周期操作、凭据加密和审计追踪等核心能力。本路线图用于记录从管理员视角仍需打磨的产品问题，并作为后续需求讨论和实施排期的入口。

本文件描述规划方向，不直接替代具体功能的 PRD 和架构设计。某项优化进入实施前，仍必须先将确定后的业务规则写入 `docs/prd.md`，将数据、接口、安全和异常处理方案写入 `docs/architecture.md`，涉及接口时同步更新 `api/openapi.yaml`。

## 2. 当前管理员能力评估

### 2.1 已具备的基础能力

- 管理员可以查看、筛选和操作全部账号的安装包、环境、实例配置和部署服务。
- 普通账号的数据访问范围由后端按所属账号强制隔离。
- 管理员可以新增账号、重置密码、启用、禁用和删除无业务数据的账号。
- 初始管理员和当前登录账号受到禁用、删除保护。
- 管理员可以查看全部账号的关键审计事件，并按条件筛选、查看详情和导出 CSV。
- SSH 密码加密保存，登录密码只保存不可逆哈希。
- 安装、启动、停止和重置具有异步状态、环境级互斥及实时执行日志。

### 2.2 当前产品阶段判断

当前系统已经解决“管理员能够操作所有资源”的问题，但尚未完全解决“管理员如何高效治理整套系统”的问题。现有体验主要围绕单个资源页面展开，缺少全局概览、集中操作、风险提醒和账号生命周期闭环。

下一阶段不宜单纯增加更多按钮，应优先建立以下四种管理员能力：

1. **全局感知**：快速判断系统当前是否健康、哪里需要处理。
2. **范围明确**：任何跨账号查看和操作都能清楚识别数据范围与最终归属。
3. **集中处置**：执行中、失败和历史操作可以在统一入口追踪与恢复。
4. **治理闭环**：账号入职、使用、禁用、资源交接和删除形成完整流程。

## 3. P0：优先优化

### 3.1 管理员总览

#### 当前问题

管理员登录后直接进入安装包管理，无法快速掌握系统规模、服务健康度和待处理风险。

#### 建议方案

增加仅管理员可见的“管理总览”首页，至少展示：

- 账号总数、启用账号数、禁用账号数。
- 安装包、环境、已安装服务和运行中服务数量。
- 当前执行中的操作数量。
- 最近 24 小时失败、超时和中断操作数量。
- SSH 未校验、长期未校验和主机指纹异常的环境数量。
- 最近 24 小时高风险审计与登录失败数量。
- 需要管理员处理的异常列表，并可直接跳转到已带筛选条件的资源页面。

总览首先服务于异常发现，不应堆叠与处置无关的装饰性图表。

### 3.2 数据范围与资源归属

#### 当前问题

顶部账号选择器实际控制的是列表数据范围，但容易被误解为“当前操作身份”或“新增资源所属账号”。管理员筛选某个普通账号后新增资源时，资源仍可能默认归管理员本人，产生认知偏差。

#### 建议方案

- 将顶部“全部账号”选择器明确命名为“数据范围”。
- 页面持续展示“当前查看：全部账号 / 某账号”，不能只依赖选择框当前值。
- 管理员新建安装包或环境时显示“所属账号”字段，默认当前管理员本人。
- 允许管理员显式选择其他账号作为新资源归属，但必须展示提示并写入高风险审计。
- “数据范围”筛选不得影响新增表单的默认归属；新增资源始终默认当前登录管理员，只有管理员显式选择后才代其他账号创建。
- 管理员修改、删除或操作其他账号资源时，在确认信息中同时展示资源名称和所属账号。
- 对跨账号危险操作采用更强确认，例如要求再次确认所属账号或输入资源名称。

### 3.3 全局操作中心

#### 当前问题

安装、启动、停止和重置的执行结果主要存在于即时弹窗中。管理员关闭弹窗或切换页面后，缺少统一入口查看所有账号正在执行或已经完成的操作。

#### 建议方案

新增“操作中心”，提供：

- 执行中、排队中、成功、失败、超时和中断操作列表。
- 按操作账号、资源所属账号、服务类型、环境、操作类型、状态和时间筛选。
- 重新打开实时或历史执行日志。
- 展示操作阶段、持续时间、退出码、失败摘要和关联请求 ID。
- 从失败操作直接进入对应环境、配置或安装包页面。
- 对安装失败提供明确的推荐动作，例如查看日志、重置残留状态、校验 SSH 或检查安装包。
- 管理员总览中的执行中和失败指标直接跳转到操作中心。

审计日志用于追责，操作中心用于运维处置，两者应通过操作 ID 相互关联，但不能合并成同一个页面。

### 3.4 账号生命周期与资源交接

#### 当前问题

有业务数据的账号不能删除是正确的安全约束，但当前管理员只会收到“仍有资源”的拒绝，缺少资源盘点和交接路径。

#### 建议方案

账号管理增加详情能力：

- 安装包、环境、服务和最近操作数量。
- 最近登录时间、来源 IP 和最近操作时间。
- 当前有效会话数量及“强制下线”。
- 最近登录失败和高风险审计。
- 创建时间、创建人、角色和启用状态。
- “查看该账号资源”快捷入口。

账号退出流程建议为：

1. 禁用账号并撤销全部会话。
2. 盘点该账号全部资源和未完成操作。
3. 将资源批量转移给指定账号，或按安全顺序完成清理。
4. 展示转移结果和不能转移的原因。
5. 确认无业务数据后删除账号。

资源转移必须保留审计历史中的原所属账号快照，并对新归属产生单独审计事件。

### 3.5 管理员风险通知

#### 当前问题

审计日志和失败记录属于被动查询，管理员无法及时知道需要关注的风险。

#### 建议方案

先增加站内通知中心，聚合以下事件：

- 10 分钟内连续登录失败达到阈值。
- 账号被禁用、删除或被管理员重置密码。
- 安装、启动、停止或重置失败、超时或中断。
- SSH 主机指纹变化。
- 已安装服务连续不可达。
- 跨账号删除、配置修改和数据导出。
- 数据目录空间不足或审计清理失败。

通知需要支持未读状态、确认处理和跳转到相关资源。企业微信、钉钉和通用 Webhook 可作为后续扩展，第一版先完成站内闭环。

### 3.6 P0 验收收口

P0 主功能已经完成以下验收收口：

- 总览补充安装包和最近 24 小时登录失败指标，并确保指标跳转携带有效筛选。
- 操作记录保存关联请求 ID；操作中心与审计通过操作 ID 双向跳转，并按失败类型跳转到对应资源页面。
- 风险通知使用稳定去重键，避免应用重启或连续失败期间重复创建同一未处理事项；增加通知保留期。
- 操作记录与 JSONL 日志增加可配置保留期，环境删除仍保留期限内的运维历史。
- 补充管理员权限、通知去重、版本引用保护、配置回滚和主要前端交互测试，并加强 OpenAPI 契约校验。

## 4. P1：提升管理效率

### 4.1 安装包版本治理

- 每次上传文件创建一个不可变版本，服务类型保存独立的“当前版本”指针；仅修改当前版本备注不创建新版本。
- 历史版本默认保留 10 个，可通过部署参数调整；清理只删除超出保留数且既非当前、也未被环境引用的旧版本。
- 展示版本 ID、摘要、大小、上传人、上传时间、版本备注和校验结果。
- 展示使用该版本的环境数量，以及已安装版本与最新版本的差异。
- 支持将兼容的历史版本重新设为当前版本；切换只影响后续安装，不自动修改或重装现有环境。
- 增加 CPU 架构兼容性标识和安装包校验结果。
- 当前版本和已被环境引用的版本不得删除；删除服务类型时必须不存在已安装环境，并清理其全部本地版本文件。

本轮以可验证的包结构、配置格式/路径和默认端口作为兼容性信息。CPU 架构自动识别及人工兼容性标签暂缓，后续与跨架构批量运维一并设计，不阻塞本轮完成。

### 4.2 配置版本、差异与漂移

- 保存前使用当前有效配置与待保存配置展示并排差异；内容未变化时不创建修订。
- 每次手工保存和回滚都创建不可变修订，记录操作者、时间、来源和来源修订，支持查看和回滚。
- 区分安装包模板、DP 实例配置和远端实际配置。
- 检测远端配置是否被绕过 DP 人工修改。
- 疑似密钥、Token 和密码字段默认遮罩。
- 管理员批量查看同服务类型在不同环境上的差异，但默认不允许直接批量覆盖。

本轮已确认范围为“保存前差异、修订历史和回滚”。远端实际配置采集、漂移检测、批量对比和敏感字段智能遮罩另行设计，不阻塞本轮完成。

### 4.3 批量运维

优先支持低风险批量操作：

- 批量 SSH 校验。
- 批量健康检查。
- 批量启动和停止。
- 按账号、服务类型、环境标签或搜索结果选择目标。
- 设置并发数并展示执行进度。
- 操作前展示目标数量、账号范围和风险提示。
- 完成后生成可导出的汇总结果。

批量安装和批量重置风险更高，应在低风险操作稳定后实施，并使用加强确认与并发保护。

### 4.4 资源标签与分组

- 本轮以环境为标签载体；服务实例继承所属环境的标签，安装包不直接绑定环境属性标签。
- 标签使用“分组 + 值”表达，例如“环境阶段 / 生产”“区域 / 华东”“项目 / 智慧交通”，账号内同一组合唯一。
- 支持新增、重命名和删除标签，并在环境新建、编辑时维护标签；删除标签只解除关联，不删除环境。
- 环境管理、服务管理共享标签展示和组合筛选；管理员操作中心使用操作发起时保存的标签快照筛选，避免后续改名、解绑或删除改变历史结果。
- 管理总览允许按标签限定环境、服务和操作类指标，账号、安装包、安全审计和通知等全局指标保持全局口径，并明确提示筛选影响范围。
- 多个标签默认使用“同时满足”语义。管理员可以查看全部账号的标签，也可以按数据范围缩小标签候选项；普通账号只能查看、维护和使用自己的标签。
- 标签不得替代账号权限边界，只用于组织与检索。环境只能关联其所属账号的标签；资源交接时按“分组 + 值”在目标账号下复用或创建等价标签。
- 环境 JSON 导出升级为 schema v2 并包含标签；导入兼容 v1，v1 环境按无标签处理，v2 在目标账号下复用或创建标签。

#### 本轮验收结果（2026-08-14）

- 已完成账号内标签字典、新增/修改/删除、环境原子关联和前后端权限隔离。
- 已完成环境、服务、管理员总览和操作中心的统一多标签 AND 筛选，并在环境、服务和操作列表展示标签。
- 已完成操作标签稳定 ID 与文本快照；标签重命名、删除及环境删除后，历史展示和既有标签筛选不漂移。
- 已完成账号资源交接时的等价标签映射，以及环境导出 schema v2、导入 v1/v2 兼容和原子 upsert。
- 已补充标签唯一性、跨账号拒绝、多标签交集、历史快照、资源交接、导入导出和 OpenAPI 路径测试；`go test ./...`、`go test -race ./...`、`go vet ./...`、前端测试与生产构建均通过。

### 4.5 可扩展的账号安全

- 第一阶段展示会话的登录时间、最近活动、来源 IP、浏览器/客户端和过期时间；本人可撤销指定会话，管理员可查看并撤销任意账号的指定会话，既有“全部下线”能力继续保留。
- 管理员重置密码时默认要求账号首次登录后强制改密，也可显式取消；待改密账号登录后只允许查询本人、修改密码和退出，不能访问业务资源。
- 初始管理员的环境变量密码和管理员新增账号时分配的密码均作为临时密码；初始化管理员及所有新账号首次登录必须由本人改密，创建账号时不允许取消。既有正常账号在升级时不追溯标记。
- 登录失败按规范化用户名和可信来源 IP 两个维度限流：任一维度 10 分钟内达到 5 次失败后进入指数退避，首次 30 秒、最长 15 分钟；成功登录清除对应失败状态。
- 启用且连续 90 天未成功登录的非初始管理员账号生成站内提醒；从未登录账号从创建时间起计算。天数可通过部署参数调整，成功登录后自动关闭既有提醒。
- 初始管理员和其他管理员优先支持 TOTP 二次验证。
- 当团队规模扩大时，再评估只读审计员、运维操作员和账号管理员等有限角色，避免所有管理人员都获得最高权限。

#### 第一阶段实施范围（2026-08-14）

- 本轮实现会话明细与单会话撤销、管理员重置后强制改密、登录失败持久化限流和长期未登录提醒。
- 本轮不实现 TOTP，也不扩展角色模型；二者作为后续独立功能，避免认证流程一次引入过多不可逆变更。

#### 第一阶段验收结果（2026-08-14）

- 已完成本人及管理员会话明细、当前会话识别、指定会话撤销和既有全部下线能力；会话 Token 及摘要不进入接口响应或审计。
- 已完成管理员重置密码默认强制改密、服务端受限会话、独立改密引导和改密后重新登录闭环。
- 已完成初始化管理员和所有新建账号默认强制首次改密，且不追溯影响升级前既有正常账号。
- 已完成用户名与可信来源 IP 双维度持久化限流、指数退避及限流审计聚合；应用重启不能清除退避状态。
- 已完成长期未登录账号每日检查、稳定通知去重、成功登录自动处理提醒及 `DP_STALE_ACCOUNT_DAYS` 部署参数。
- 已补充迁移、限流、强制改密、会话撤销、长期未登录筛选和审计聚合测试；`go test ./...`、`go test -race ./...`、`go vet ./...`、前端类型检查、测试与生产构建均通过。

## 5. P2：中长期治理能力

- 审计常用筛选条件、风险事件关联时间线和周期性导出。
- 外部只追加审计存储或签名归档，以提高防篡改能力。
- 企业微信、钉钉及通用 Webhook 告警。
- 系统设置页：版本、数据目录空间、数据库状态、审计保留期及非敏感运行参数。
- 升级前检查、数据库迁移状态、版本兼容性和回滚提示。
- 账号或项目级资源配额，防止单个账号占用过多安装包空间或远程操作并发。
- 更细粒度的只读、操作、账号管理和审计权限。

## 6. 已暂缓但重要：备份、恢复与迁移

完整的一键导出、导入和无痛迁移当前暂缓，不进入近期实施范围。但从管理员灾备角度，仍建议先提供较轻量的“备份健康检查”：

- 展示数据库、安装包、操作日志和 `.env` 的备份范围。
- 展示数据目录当前大小、剩余空间和增长趋势。
- 提醒 `DP_MASTER_KEY` 丢失或变化会导致 SSH 密文不可解密。
- 提供备份完整性检查命令和最近一次验证结果。
- 在版本升级前明确提示先备份 `data/` 与 `.env`。

只有在重新确认完整迁移需求后，才恢复该功能的详细设计与编码。

## 7. 推荐实施顺序

已完成项目不再占用推荐队列。以下顺序保留为恢复实施时的参考，但当前全部暂停，不构成活跃开发队列：

1. **管理员 TOTP 二次验证**：在安全基线稳定后，为高权限账号增加第二因子和恢复流程。

## 8. 路线图维护规则

每个优化项使用以下状态：

- `待讨论`：方向已提出，但产品规则尚未确认。
- `已确认`：范围和关键规则已经确认，可以进入详细设计。
- `设计中`：正在更新 PRD、架构和接口文档，尚未编码。
- `实施中`：相关文档已经完成，正在修改代码。
- `已完成`：代码、测试、部署说明和文档均已同步并通过验证。
- `已暂缓`：当前不实施，保留背景和恢复条件。

状态变化必须在实施该功能的同一提交中更新，不能只改代码、不维护路线图。每完成一个功能，至少同步更新上方状态表、本文对应方案和“最近更新”日期；功能只有在正式文档、代码、测试和部署说明均一致后才能标记为 `已完成`。

本文件是实施期间使用的临时路线图，不作为功能完成后的永久规范。所有已确认规则必须持续沉淀到 PRD、架构、OpenAPI、README 或部署文档中。当状态表中全部已纳入范围的事项均为 `已完成` 或 `已暂缓`，并确认不存在只记录在本文件中的有效规则后，应在最后一次收尾提交中：

1. 将仍有长期价值的产品和技术规则迁移到对应正式文档。
2. 删除 README、PRD 和架构文档中指向本文件的链接。
3. 删除本文件。

功能完成后不应仅为了保留历史而继续维护本文件；实施历史由 Git 提交记录追溯。

## 9. 文档先行约定

从本文件建立之日起，所有新增功能和会改变用户行为的修改均遵循以下流程：

1. **编码前更新文档**：先明确产品规则、权限边界、交互、异常处理和兼容策略。
2. **按影响范围更新**：
   - 产品行为更新 `docs/prd.md`。
   - 数据模型、组件边界、安全、并发和故障策略更新 `docs/architecture.md`。
   - HTTP 接口更新 `api/openapi.yaml`。
   - 环境变量、部署或运维步骤更新 `.env.example`、`README.md` 和部署说明。
   - 管理员路线图功能更新本文件的状态和实际范围。
3. **实现后再次校准**：若实现中发现设计不可行或规则发生变化，必须先修正文档，再完成代码。
4. **文档与代码共同提交**：功能提交必须包含对应文档变更；没有完成文档同步的功能不视为完成。
5. **测试覆盖文档规则**：权限、数据归属、危险操作、错误提示和兼容性等关键规则必须有相应验证。
